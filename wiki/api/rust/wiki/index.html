wiki: one static site from every repo in a pull workspace.

Each repo’s README is its entry page, its docs/ folder becomes pages, and rustdoc / LDoc / JSDoc produce its code reference. Git object ids (blob, tree and patch ids) decide what has to be regenerated: see state.

Modules§

apidoc 🔒
Code reference per repo, by each language’s own tool, into .build/api/<repo>/<tool>/: rust: cargo doc --no-deps (rustdoc) lua: LDoc js: JSDoc A tool that is missing or fails only warns: the site still builds. A reference is rebuilt only when the repo’s source id (see state) or its wiki.toml settings changed.
bundle 🔒
Client assets into dist/_assets: rolldown (embedded) bundles and minifies assets/main.js with its npm imports; lightningcss bundles assets/style.css (Bootstrap via @import) plus syntect’s CSS for the highlight classes.
collect 🔒
The repos to publish: pull status --json merged with wiki.toml.
markdown 🔒
Markdown for docs from many repos (comrak): GFM tables, autolinks, smart punctuation, {#id} heading attributes, syntect highlighting at build time (CSS classes, bat’s syntaxes, no client JS), and data-sourcepos on every block so Radar can map a selection back to its source line. Links are rewritten afterwards with lol_html, which covers markdown and raw HTML alike.
render 🔒
Pages: every repo’s README (its entry page) and docs/ folder, plus the wiki’s own pages/*.jinja, through minijinja templates (templates/).
state 🔒
What needs regenerating, decided with git object ids.
