Lua hooks for ycode, in the spirit of Logos/MobileSubstrate tweaks.

Every action dispatched in the app (keyboard, menus, command palette, dispatch_action) goes through [gpui::App::intercept_actions]. Hook files can wrap any action by name, call through to the original with %orig, replace its arguments, or swallow it, and can define new actions with %new that are bound to keys through ycode::Run.

Files are loaded from <config dir>/hooks/ in name order: *.x.lua files go through the Logos-style preprocessor in preprocess; plain *.lua files can use the same runtime via ycode.hook(name, fn), ycode.new_action(name, fn) and ycode.ctor(fn). Run ycode: reload hooks to reload them.

Modules§

panel
gpui.register_panel{...}: dock panels rendered from Lua, like gpui.open_window.
preprocess
Logos-flavoured preprocessor for *.x.lua hook files.
runtime
mlua runtime: loads hook files, keeps the hook index, and runs %orig chains. Independent of gpui; the app side is reached through Host.
status
ycode.status_button{...}: buttons in every workspace’s status bar, defined in Lua.
ui
gpui for Lua: gpui.open_window{...} / gpui.register_panel{...} render a tree of Lua tables on every frame, built from Zed’s own ui components so Lua panels look like the native ones without any styling in the plugin.
